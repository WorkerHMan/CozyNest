# CozyNest 整体内容与界面设计蓝图

> 本文是**信息架构与内容设计**的真源，配合 `MASTER.md`（视觉令牌）与 `pages/<页面>.md`（页面级覆盖）使用。
> 检索依据：ui-ux-pro-max（domain: ux / landing / product / chart / gsap，stack: nextjs / threejs / shadcn）。

---

## 0. 一句话定位

**一个人的数字窝：技术内容为骨，娱乐与创作内容为肉，全部住在一个可换皮肤、有生命的界面里。**

- 骨架部分是**技术**（博客 / 知识库 / 作品集 / 资源 / 工具）→ 需要克制、高可读、适合长文。
- 肉的部分是**娱乐创作**（音乐 / 视频 / 相册 / 书籍 / 二次元看板 / 小游戏）→ 需要活泼、有情绪、有动效。
- 这两者**不该用同一套视觉强度**。这是本蓝图最重要的一个结论，见 §1。

## 1. ⚠️ 需要你拍板的第一个决策：视觉方向冲突

我用**真实需求**重新检索后，技能给出的方向与我上一轮落盘的 `MASTER.md` **完全相反**：

| | 当前 `MASTER.md`（上一轮生成） | 真实需求检索结果 |
|---|---|---|
| 适用类别 | **API Developer Portal** | Feature-Rich Showcase（多模块门户） |
| 风格 | Minimalism & Swiss（克制、白空间） | **Vibrant & Block-based**（大胆、活泼、块状、双色调） |
| 适用场景 | 企业应用、仪表盘、文档站、专业工具 | **娱乐、游戏、面向年轻人、消费级** |
| 字体 | JetBrains Mono + IBM Plex Sans | **Righteous（标题）+ Poppins（正文）** |
| 情绪 | code / developer / hacker | **music / fun / energetic / bold** |

原因很清楚：上一轮我用的是 `"interactive 3d developer tools platform"` 这个检索词，得出的是"开发者门户"。而你这次给的完整需求里有**音乐、视频、小说、相册、二次元看板、小游戏、AI 互动、广告**——这是娱乐型个人门户，技能据此给出的是活泼方向。

**三个选择：**

| 方案 | 内容 | 代价 |
|---|---|---|
| **A. 双层系统（我建议）** | `MASTER.md` 保持瑞士克制风作为**全局外壳 + 技术模块**；为娱乐模块写 `pages/` 覆盖，采用 Vibrant & Block（更饱和的强调色、块状卡片、更活泼的动效与字体权重） | 需要多维护一层覆盖规则；两套强度需要我明确边界 |
| B. 全部改成 Vibrant & Block | 用 `--force` 重新生成 MASTER，全站活泼 | 会丢掉已有的对比度实测成果；长技术文章在活泼风下可读性下降 |
| C. 保持现状（全站瑞士克制） | 不动 MASTER | 音乐/相册/二次元模块会显得冷、没有情绪 |

> 技能明确规定：**`--force` 覆盖 `MASTER.md` 必须获得你明确授权**，所以我没有动它。

## 3. 导航策略（17 个模块怎么放）

技能把 **overloaded nav（导航过载）** 列为反模式，且移动端底部导航上限 5 项。所以**不能把 17 个模块平铺进顶部导航**。

### 桌面端：一级 5 项 + 「更多」超级菜单

| 位置 | 内容 |
|---|---|
| 一级（常驻） | 首页 · 博客 · 作品集 · 音乐 · 更多 |
| 「更多」菜单分三栏 | **技术**：知识库 / 资源 / 工具 · **内容**：书籍 / 视频 / 相册 · **互动**：二次元看板 / AI / 留言板 / 关于 |

按 `landing` 检索里 `enterprise-gateway` 的规则：*"Path selection (I am a...) + Mega menu navigation"* —— 用超级菜单做**路径选择**，这是该模式对"模块很多的站点"的标准解法。

### 移动端：底部导航 ≤5

首页 · 博客 · 音乐 · 相册 · 更多（其余进抽屉）

### 面包屑（技能：3 层以上才用）

只在真正嵌套的地方出现：`首页 > 博客 > STM32 > 时钟树梳理`。
一级页面**不要**加面包屑（"flat single-level sites 不该用"）。

### 导航的两条硬规则（来自检索）

1. **壁纸门厅下滑后才显示导航栏**——你的设计。要注意 `landing` 检索明确要求：*"Keep navigation visible"*、*"Preserve a normal vertical navigation path"*。所以：**门厅必须有可见的向下指示**，且**键盘 Tab 第一次落在门厅内就要能到达导航**（不能把导航藏在滚动之后导致键盘用户进不去）。
2. **不得劫持滚动**（scroll-jacking）——`horizontal-scroll-journey` 与 `scroll-triggered-storytelling` 都要求：*"disable scroll-jacking under reduced motion"*、*"Pause scroll animation when offscreen or hidden"*。

## 4. 全局特性设计（你列的「特点」）

### 4.1 点击触发小点：功德 / 富强

随机结果的互动彩蛋。

- **无障碍**（优先级 1）：结果不能只靠视觉。需要 `aria-live="polite"` 播报（"功德 +1" / "富强 +1"），否则屏幕阅读器用户完全不知道发生了什么。
- **动效降级**（优先级 7）：`prefers-reduced-motion` 下直接显示结果文字，不做粒子/飘字。
- **反馈要即时**：点击后 100ms 内必须有视觉响应（技能：*"Instant state changes (0ms)"* 是反模式，但也不能超过 100ms 才给反馈）。

### 4.2 界面切换加载动画

技能 `nextjs` 栈的规则很明确，而且**用框架原生能力**即可：

| 规则 | 做法 |
|---|---|
| "Handle loading states" → `loading.tsx` alongside `page.tsx` | 每个路由放 `loading.tsx`，不要手写 loading 状态管理 |
| "Avoid layout shifts"（**High**）→ Skeleton loaders aspect ratios | 用 **Skeleton** 而不是 spinner；骨架尺寸必须和真实内容一致，CLS < 0.1 |
| 过渡本身 | Next 16 的 `Link` 支持 `transitionTypes`，配合 React `ViewTransition` 做路由转场；`cacheComponents` 已启用，静态外壳先到、动态内容流式补齐 |

> 注意：我上一轮查 `--stack shadcn` 时也得到同一条「Use Skeleton for loading」，当时没有适用场景；**你现在的加载动画正是它的用例**。

### 4.3 磁力棒光标

参考图：蓝→粉渐变的辐射状短棒 + 二次元头像。

`MASTER.md` 的 Motion 段（Complex 档）已经给了确切参数：

```js
const onPointerMove = (e) => { const r = el.getBoundingClientRect();
  xTo((e.clientX - r.left - r.width / 2) * 0.3);
  yTo((e.clientY - r.top - r.height / 2) * 0.3); };
```
- 时长 **300–500ms**，缓动 `elastic.out(1,0.4)`
- **拉力系数封顶 0.3**：元素不能离开自己的点击热区
- ⚠️ **每屏最多 1–2 个焦点元素**用磁吸，多了就吵
- `will-change: transform` 提升合成性能
- **触摸设备没有 hover**（优先级 2：不能只依赖 hover）→ 磁吸必须是**增强**，不能是唯一反馈
- reduced-motion 下**停在居中终态**，不是消失

### 4.4 设置面板（按你的截图重做）

你的截图里有 6 组控制，比我现在实现的（只有亮暗 + 中英文）丰富得多：

| 控制 | 取值 | 实现方式 |
|---|---|---|
| 夜间模式 | 开 / 关 | 已有 `next-themes`（class 策略） |
| 字体 | Sans Serif / Serif | 切换 `--font-sans` ↔ 一个 serif 变量 |
| 阴影 | 浅 / 深 | 切换 `--shadow-*` 令牌档位 |
| 滤镜 | 关闭 / 日落 / 暗化 / 灰度 | 页面级 CSS `filter`，作用于壁纸与图片容器 |
| 圆角 | 滑块 | 直接写 `--radius`（shadcn 所有圆角都由它派生，改一处全站生效） |
| 主题色 | 取色器 | 写 `--brand` / `--primary`（成对更新 `--primary-foreground` 保证对比度） |

**关键工程点**：这 6 项都必须**持久化到 cookie 或 localStorage 并在首屏前应用**，否则会闪。夜间模式已经这样做了，其余 5 项要走同一套「阻塞脚本 + class/变量」机制；圆角与主题色写 `<html>` 上的内联 CSS 变量最省事。

## 5. 首页解剖

`product` 检索里 Portfolio/Personal 的落地模式是 **Storytelling-Driven**，`landing` 检索给的区块顺序可直接采用。

```
① 壁纸门厅（100vh）
   全屏壁纸轮播 · 左右切换 · 信条/一句话文案 · 向下指示
   └─ 轮播硬性要求（enterprise-gateway 规则）：
      · 控制器必须键盘可操作（← → 与按钮都要能聚焦）
      · 必须能暂停自动轮播（auto-rotation pause）
      · 焦点进入时停止轮播（stop on focus）
      · reduced-motion：停在静态帧，不自动播放
      · 预留宽高比，避免 CLS（技能 High）
② 下滑 → 导航栏浮现（sticky）+ 个人标（点击 → 回到门厅顶部）
③ 搜索框（全站搜索，prominent —— FAQ/Doc 模式的 CTA 位置）
④ 模块卡片网格（4–6 张，Feature-Rich Showcase 的核心区块）
   技术 / 内容 / 互动 三集群各取代表
⑤ 倒计时 + 时间进度
   距离春节 N 天 + 今日/本周/本月/本年 百分比
   └─ 用 role="progressbar" + aria-valuenow，不能只画个条
⑥ 订阅区：RSS + 邮件
⑦ 页脚：网站信息 / 版权 / 合作 / 作者简介 / 统计
```

### 页脚统计（含隐私提醒 ⚠️）

你列了：当前访问者 IP、今日访客数、今日访问、总文章数、总浏览量、站点更新信息。

- **总文章数 / 总浏览量 / 更新时间**：安全，从数据库或构建期统计来。
- **今日访客 / 今日访问**：需要服务端计数（KV 或数据库 + 简单去重）。
- ⚠️ **「当前访问者 IP」公开显示是隐私问题**：等于把每个访客的 IP 展示给所有人（也包含你自己）。IP 属于个人数据，公开张贴可能违反 GDPR/《个人信息保护法》。
  **建议改为**：只显示你自己的服务器出口信息，或者显示"你的访问来源地区（粗粒度，如"中国·上海"）"，或干脆只显示"今日访客 N 人"。
  如果你坚持要显示 IP，至少必须**默认关闭**并让访客自己选择是否展示。

## 6. 各模块页面解剖

### 6.1 博客（`/blog`）

四个视图 + 一个彩蛋入口，用 **Tabs** 承载（符合"路径选择"）：

| 视图 | 路由 | 关键设计 |
|---|---|---|
| 精选 | `/blog` 默认 | 大卡片 + 摘要，1–3 篇 |
| 分类 | `/blog?category=` | 按技术分类（C/C++、STM32、FreeRTOS、Linux、CV…） |
| 归档 | `/blog/archive` | **GitHub 式密集点热力图**（见下方约束） |
| 标签 | `/blog/tag/<tag>` | 标签云 + 列表 |
| 星图 | `/blog/starmap` | 文章 = 星点，点击进入正文；集群 = 主题 |

**归档热力图的无障碍约束**（`chart` 检索，Heat Map 条目）：
> *"Print values or symbols in cells and use texture/labels in addition to the color scale. **Do not rely on color alone.**"*

也就是说：密集点不能只用颜色深浅表达数量——每格要有可读的值或符号（hover/tap 显示、或密度分级用不同形状），否则色觉障碍用户读不出来。

**文章页**：长文阅读优先。正文按优先级 6 要求 **16px 基准、行高 1.5**，等宽只用于代码。

### 6.2 作品集（`/projects`）

参考 `bytexiang.cloud/projects`。展示型 → 卡片网格 + 详情页（技术栈、架构图、成果）。

### 6.3 资源汇总（`/resources`）

他人文章 / 他人项目 / 软件研发资源。本质是**目录**：需要分类 + 搜索 + 外链标识（外链要有 `rel="noopener noreferrer"` 与明确的外链图标）。

### 6.4 书籍（`/library/books`）

小说 + 专业书。**两套阅读体验**：小说需要沉浸/护眼（衬线、可调字号、夜间），专业书需要代码块与目录。建议用 `pages/library-books.md` 单独覆盖排版规则。

### 6.5 音乐（`/library/music`）

歌单播放器。**必须有的状态**（优先级 8「Feedback」）：加载中 / 播放中 / 暂停 / 缓冲 / 加载失败 / 限流。
⚠️ `MASTER.md` 的反模式里明确写着 **"missing rate-limit state"**——音乐/视频/AI 这三个模块都要处理限流与配额用尽。

### 6.6 视频（`/library/video`）

同音乐，额外：**不要自动播放有声视频**；轮播/预览必须可暂停（同轮播规则）。

### 6.7 相册（`/gallery`）

图片密集型 → 技能 `nextjs` 栈 **High** 级规则：*"Use next/image for optimization — `<Image>` component for all images, don't use `<img>` directly"*；配合 WebP/AVIF、懒加载、**预留宽高比防 CLS**。灯箱要键盘可达（Esc 关闭、← → 切换、焦点锁定）。

### 6.8 工具栏（`/tools`）

在线工具（JSON / Base64 / 时间戳…）+ 小游戏。
⚠️ 我上一轮已经为它修好了一个真实缺陷：工具页是**输入密集型**，而深色模式的可交互边界原本只有 1.80:1。已拆出 `--border-strong` / `--input`（实测 3.44 / 3.73 / 3.06，全部达标）。
表单规则（优先级 8）：**可见标签**（不能只用 placeholder）、错误显示在字段旁、辅助文本、渐进披露。

### 6.9 二次元看板（`/board`）

展示型 + 情绪型 → 这是**最适合 Vibrant & Block 方向**的页面，建议独立 `pages/board.md` 覆盖：更饱和的色、块状拼贴、更大的动效预算。

### 6.10 AI 互动（`/ai`）

对话界面。需要：流式输出、**错误与限流状态**、消息可复制、键盘可达、长对话虚拟化（技能：`virtualize-lists`）。
⚠️ 这是**唯一需要真正后端**的重模块（API Key、配额、计费）。

### 6.11 留言板 / 举报反馈（`/guestbook`）

需要注册登录 + 内容审核 + 举报流程。**反垃圾**必须一开始就设计（否则上线一周就被灌满）。

### 6.12 广告

三条硬约束：
1. **必须预留尺寸**，否则广告加载时会把正文顶下去（优先级 3：CLS < 0.1，技能列为 High）。
2. 广告不能伪装成内容（明确的"广告"标识）。
3. 首屏门厅**不要放广告**——那是最需要沉浸的地方。

## 7. 动效与降级总规范

技能检索给出的**最强约束**（`ux`：Excessive Motion，**High**）：

> **每个视图最多动画 1–2 个关键元素。** 反例就是 *"animate-bounce on 5+ elements"*。

你的需求里有：磁力光标 + 路由转场 + 壁纸轮播 + 倒计时 + 点击飘字 + 二次元看板 + 播放器动效 + 3D 场景。**这些不能同时动。**

分配方案：

| 页面 | 允许的 1–2 个主运动 | 其余一律静态 |
|---|---|---|
| 门厅首页 | 壁纸轮播 + 磁力光标 | 倒计时、卡片、页脚静态 |
| 博客列表 | 滚动渐显（stagger ≤ 8 项） | 分类/标签/热力图静态 |
| 文章页 | 阅读进度条 | 正文不动 |
| 音乐/视频 | 播放器波形/封面 | 列表静态 |
| 二次元看板 | 看板主视觉 | 其余静态 |
| 3D 场景 | 场景本身 | 周围全静态 |

统一令牌（已落地在 `globals.css`）：`--motion-duration-fast: 200ms` / `base: 350ms` / `slow: 600ms`，`--motion-ease-out`。

**所有动效的统一降级**：`prefers-reduced-motion: reduce` → **停在最终可读状态**，不是消失、不是留白。这一条已经用全局兜底实现（动画降到 0.01ms）。

## 8. 无障碍与性能硬约束（交付前逐条核）

- [ ] 正文对比度 ≥ 4.5:1；**可交互边界 ≥ 3:1**（已实测 21 项全过）
- [ ] 每个可操作控件有可见焦点环
- [ ] 键盘可达：轮播、灯箱、菜单、播放器、对话
- [ ] 轮播/自动播放：可暂停、失焦停止、reduced-motion 静态终态
- [ ] 图标一律 SVG（**禁止 emoji 当图标**）
