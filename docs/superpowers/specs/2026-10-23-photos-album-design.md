# 相册（Photos）设计

日期：2026-10-23
状态：待评审
现有代码：`src/app/[locale]/photos/page.tsx`（占位页）

---

## 1. 意图

这个站点目前所有内容都是"写下来的"：文章、项目、歌单。相册是第一个"攒下来的"模块——它的内容不靠写，靠往里面倒。

它要同时做到三件互相拉扯的事：

1. **回看**：一眼看见自己走过哪些地方。要的是那张图本身，不是筛选器。
2. **找**：说"小狗"就能找到，不靠回忆年月和文件夹。这件事必须真的能用，不能是演示。
3. **收**：多台手机、电脑文件夹、随手记，全部汇进来，汇进来之后**敢删手机**。

再加一条界线：**公开的给人看，其余只有我能进**。这一条决定了整个架构，见 §4.1。

---

## 2. 目标

- 打开 `/photos`，不看任何控件就知道"我去过哪、照片有多少、从哪年开始"。
- 地图上一共 23 个城市，点一个城市，看到那座城市的照片，按时间排。
- 搜"小狗"，出现狗的照片；搜"海 2023"，只剩 2023 年的海。
- 从旧手机导 8000 张照片：不重复入库、不用手动打标签、导完给一张"可以删"的清单。
- 拖进一个文件夹，什么都不选，照片自己进去、自己归类、自己有时间地点。
- 公开相册里的每一张，都是我从私库里挑出来发布过的。没发布的，公开站上根本不存在。

## 3. 非目标（这一期不做）

- 视频（`/video` 是另一个模块）。导入时遇到 `.mov/.mp4` 跳过并记一行日志。
- RAW（`.dng/.cr2/.arw`）：先允许入库归档，不生成预览，标记为"未转码"。
- 多用户、家庭共享账号、评论、点赞、社交。
- 在公网上提供任何私人内容的读接口。这不是"以后再说"，是架构上排除。
- 修图、调色、人脸识别（人脸是隐私雷区，收益不明显）。
- 原生手机 App。手机用浏览器/PWA 就够。

## 4. 核心决断

下面每一条都是**我替你定的**，不是我们聊定的。不同意任何一条都可以推翻，但推翻会牵连别的条目。

### 4.1 一个库，两扇门

一个库（私库）是唯一真相源；公开相册是这个库"发布"出来的一份静态快照。

```
        ┌─────────────────────────────┐
        │  私库（只在你机器上）        │
        │  SQLite + 原图 + 派生图      │
        └──────────┬──────────────────┘
                   │ 挑选 → 发布（一条命令）
                   ▼
        ┌─────────────────────────────┐
        │  公开相册（进仓库，纯静态）  │
        │  webp + album.ts + 搜索索引  │
        └─────────────────────────────┘
```

为什么不是"一个站，照片带一个公开/私有开关"：那要求站点有服务端、有登录、有对象存储、有数据库，而且**私人照片的安全取决于权限代码有没有写对**。发布快照的做法把隐私换成另一件事——私人的照片从来没被复制到那个仓库里，泄露的前提是有人先手动发布它。这种保证不需要信任任何代码。

代价是"随时上传"不能在任何一台联网设备上发生，见 §6。

### 4.2 私库只在本机跑，不进公网

私库是同一个 Next 应用的第二运行模式：`NEST_LIBRARY=1` 时挂载 `/studio`，只监听 `127.0.0.1`。在 Vercel 上这个环境变量不存在，`/studio` 直接 404。

- 数据层：`better-sqlite3`（同步 API，单机够快，不需要 ORM）。
- 图片：`sharp`（libvips），缩略图与转码。
- EXIF：`exifr`（纯 JS，快，能读 GPS 与拍摄时间）；HEIC 用 `heic-decode` 兜底。
- 上传/入库是本地写盘，没有传输成本，也没有"上传进度条转圈三分钟"。

同一份代码、同一套设计系统、同一套双语字典，避免两个项目慢慢漂移。代价：`/studio` 的页面不能进静态预览，开发时要跑第二个端口或者切环境变量（见 §13）。

**手机上传是唯一获准离开 localhost 的入口**，做成显式开关，不是默认能力：

- 默认绑 `127.0.0.1`。
- `NEST_LAN=1` 时绑 `0.0.0.0`，但 `proxy.ts` 只放行 `/studio/upload` 及其 POST 端点与该页静态资源；从局域网访问其余 `/studio/*` 一律 403。
- 上传页要一个配对码：终端打印 6 位数字，30 分钟有效，换来一个只能上传的 cookie。没有配对码的访问者看到的是一张空白页。
- 手机上能做的只有"传"，不能删、不能归类、不能发布。管理只在电脑上。

这样"只监听本机"和"手机随时上传"不打架：本机是全部能力，局域网是一扇只能往里递东西的小窗。

### 4.3 公开相册是构建时的静态数据

公开侧沿用博客的做法：`src/data/album.ts` 导出照片与相册的元数据，页面是 Server Component，构建时全部预渲染。没有 API、没有数据库、没有运行时查询。

照片进仓库的体积预算：**一期上限 300 张、单张 webp ≤ 320KB、总量 ≤ 90MB**。超过就换存储（Cloudflare R2 + 自定义域名），换的时候只改 `lib/album/storage.ts` 一个适配层，页面代码不动。

### 4.4 搜索靠"导入时生成的中文描述 + 固定词表的语义标签"

"搜小狗"分两层，都在导入时算完，公开侧只做全文检索：

- **语义标签（能覆盖"小狗"）**：用 CLIP 的**图像**编码器给每张图打分（`@xenova/transformers` 跑 `clip-vit-base-patch32`，CPU 可用）。词表是固定的几十个概念（狗、猫、海、山、雪、夜、食物、建筑、花、车、人、天空…），每个概念预先算好英文文本向量，构建期存进 `config/photo-concepts.ts`。中文查询靠一张**别名表**映射到概念：`小狗 / 狗狗 / 狗 / 汪 / 柴犬 → dog`。不承诺任意自然语言，承诺这几十个概念真的好用。
- **自由描述（能覆盖"海边日落"这类）**：可选步骤，用本机 Ollama 上的小视觉模型给每张图生成**一句中文描述**（"傍晚的海边，两个人在拍照"），存进搜索文档。没有 Ollama 就跳过这一步，功能降级但不报错。
- **结构化检索**：年份、城市、相册、手动标签，永远是精确过滤，不经过任何模型。

公开侧的搜索是客户端全文（`minisearch`），索引在构建时生成。精选相册通常只有几百张，索引 gzip 后几十 KB，不是问题。真正的"任意句子找图"（向量检索）放二期，需要服务端，另议。

### 4.5 地图自己画，不引地图服务

构建期用 `d3-geo` 把 GeoJSON 投影成 SVG path 字符串（`generated/geo.ts`），页面只渲染 SVG。不引 Mapbox / 高德 / Leaflet：

- 不需要 key、没有配额、没有第三方请求，暗色风格完全可控。
- 中国视图用 Albers 投影（国内制图习惯），世界视图用 Natural Earth。
- 投影函数在构建期跑一次，运行时零依赖。

代价：没有底图细节（路网、卫星）。这个页面要的不是导航，是"我点亮了哪些地方"，省掉底图反而更清楚。

## 5. 数据模型

SQLite 单文件 `library.db`，放在 `NEST_LIBRARY_HOME`（默认 `D:\NestLibrary\`）。

```sql
-- 一张照片或一段笔记里的一张图
CREATE TABLE asset (
  id            TEXT PRIMARY KEY,          -- 短 id，公网发布时也用它
  sha256        TEXT NOT NULL UNIQUE,      -- 完全重复的唯一判据
  phash         TEXT,                      -- 感知哈希，近似重复分组的依据
  path          TEXT NOT NULL,             -- 原图相对路径 originals/2023/xxxx.jpg
  bytes         INTEGER NOT NULL,
  mime          TEXT NOT NULL,
  width         INTEGER, height INTEGER,
  taken_at      TEXT,                      -- ISO8601，带原始时区偏移
  taken_at_bucket TEXT,                    -- YYYY-MM，给时间轴用，避免每次解析
  lat REAL, lon REAL, alt REAL,
  place_id      TEXT,                      -- 反查到的城市（见 place）
  camera_make   TEXT, camera_model TEXT,
  status        TEXT NOT NULL DEFAULT 'active',  -- active | trashed | archived
  imported_at   TEXT NOT NULL,
  source        TEXT NOT NULL,             -- 导入批次，见 import_batch
  caption       TEXT,                      -- 导入时生成的描述（中文，只给搜索用）
  description   TEXT,                      -- 你自己写的那一句，会被发布出去
  visibility    TEXT NOT NULL DEFAULT 'private',  -- private | public，含义见 §5.1
  FOREIGN KEY (place_id) REFERENCES place(id)
);
CREATE INDEX asset_bucket ON asset(taken_at_bucket) WHERE status = 'active';
CREATE INDEX asset_place  ON asset(place_id)        WHERE status = 'active';
CREATE INDEX asset_public ON asset(visibility)      WHERE status = 'active';

CREATE TABLE tag (
  id TEXT PRIMARY KEY, kind TEXT NOT NULL,  -- concept | manual | place
  name TEXT NOT NULL, count INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE asset_tag (
  asset_id TEXT NOT NULL, tag_id TEXT NOT NULL, score REAL,
  PRIMARY KEY (asset_id, tag_id)
);

-- 城市/地区聚合。地图与"地点"分类都读它。
CREATE TABLE place (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, name_en TEXT,
  country TEXT, admin TEXT, lat REAL NOT NULL, lon REAL NOT NULL
);

-- 手挑的相册。三年后你还想点开的那几个。
CREATE TABLE album (
  id TEXT PRIMARY KEY, slug TEXT NOT NULL UNIQUE,
  title TEXT NOT NULL, title_en TEXT, description TEXT,
  cover_asset TEXT, created_at TEXT NOT NULL,
  visibility TEXT NOT NULL DEFAULT 'private'  -- public：这个相册整体可以发布
);
CREATE TABLE album_asset (
  album_id TEXT NOT NULL, asset_id TEXT NOT NULL, sort INTEGER NOT NULL,
  PRIMARY KEY (album_id, asset_id)
);

-- 笔记：一句话，可以带图。和照片混在同一条时间流里。
CREATE TABLE moment (
  id TEXT PRIMARY KEY, body TEXT NOT NULL, created_at TEXT NOT NULL,
  place_id TEXT, visibility TEXT NOT NULL DEFAULT 'private'  -- private | public
);

-- 导入批次：多台手机靠它区分，也给"可删清单"提供依据
CREATE TABLE import_batch (
  id TEXT PRIMARY KEY, source_label TEXT NOT NULL,  -- "红米 Note 12 旧手机" / "D:\照片\2023"
  started_at TEXT NOT NULL, finished_at TEXT,
  scanned INTEGER DEFAULT 0, added INTEGER DEFAULT 0,
  duplicated INTEGER DEFAULT 0, failed INTEGER DEFAULT 0
);

-- 发布记录：哪些照片去了公开站，什么时候发的
CREATE TABLE publish (
  id TEXT PRIMARY KEY, published_at TEXT NOT NULL,
  asset_count INTEGER NOT NULL, git_commit TEXT
);
CREATE TABLE publish_asset (publish_id TEXT, asset_id TEXT, PRIMARY KEY (publish_id, asset_id));
```

`asset.status = 'trashed'` 是软删除，30 天后由维护命令真正移除。发布过的照片被删时，公开站那一份要单独处理（§10 的"撤回"）。

```sql
-- 备份校验记录：可删清单的依据，见 §6.3
CREATE TABLE backup_check (
  id TEXT PRIMARY KEY,
  root TEXT NOT NULL,              -- 备份根目录
  manifest_at TEXT NOT NULL,       -- 备份清单生成时间
  checked_at TEXT NOT NULL,
  verified INTEGER NOT NULL,       -- 1 通过，0 不通过
  note TEXT
);
```

### 5.1 "公开"是一个标记，不是一次动作

这一条是整份设计的隐私基线，不能有歧义：

- `asset.visibility = 'public'`：这张照片可以出现在公开站。
- `album.visibility = 'public'`：这个相册整体公开，里面的照片不必逐张标记（但仍要求 `status = 'active'`）。
- **公开集合** = `visibility = 'public' 且 status = 'active'` 的照片，加上公开相册里 `status = 'active'` 的照片。
- `publish_asset` 是"这一次发了哪些"的审计快照，用来算两次发布之间的差集（新增 N / 移除 M），它不是公开集合本身。
- 照片从 public 改回 private、被 trash、或所在相册取消公开 → 下次发布算作"移除"。**移除 M > 0 时，发布必须先列出清单并要一次确认**，不允许静默移除。
- 标记动作发生在 P1 的收件箱和浏览页（一个眼睛图标，快捷键 `P`），不是只在发布页——发布页只负责把已经标好的东西发出去。

## 6. 收录（这是整个项目真正的门槛）

照片进不来，页面再好看也是空的。所以录入的默认体验定成：**倒进去，不选任何东西**。

### 6.1 三个入口

| 入口 | 场景 | 做法 |
|---|---|---|
| 拖文件夹 | 从电脑、移动硬盘、旧手机备份导 | `/studio/import` 拖进去，或 `npm run nest:import -- "D:\照片\2023"` |
| 手机上传 | 随手拍，想立刻进库 | 手机浏览器打开 `http://<电脑局域网IP>:3000/studio/upload`，多选上传 |
| 监视文件夹 | 最省事的那条 | `D:\NestInbox\` 里出现什么就吃什么。手机自动同步（相册同步/OneDrive）到它，等于永不手动 |

监视文件夹是主路径。它把"上传"这件事从流程里删掉了——照片出现在那个文件夹里就算入库，剩下的都是后台。

### 6.2 处理步骤（每张图）

1. 读文件头判类型；不认识的直接记一行 `failed`，不中断整批。
2. 算 `sha256`。已存在 → `duplicated`，直接跳过，**不复制、不占空间**。
3. 读 EXIF：拍摄时间（没有就退回文件修改时间，并标记 `taken_at_estimated`）、GPS、机型、方向。
4. 拷进 `originals/<年>/<短id>.<ext>`，源文件不动。
5. 生成派生图：`derived/<短id>/w480.webp`、`w1280.webp`、`w2400.webp`，外加 32px 的 `blur`（base64，给 `next/image` 的 blurDataURL）。
6. 算 `phash`，与已有照片比对，汉明距离 ≤ 6 的归成"相似组"（不自动删，只标记）。
7. GPS → 反查城市：离线数据（GeoNames cities15000 + 中国行政区划），最近邻匹配，无网络也能跑。
8. 可选：CLIP 概念打分、Ollama 生成中文描述。这两步失败只记警告，图片照常入库。

批量处理走队列，页面能看到进度（"正在处理 1204/8000"）。一张图 CPU 上大约 30–80ms（不含模型），8000 张十几分钟，可以挂着。

### 6.3 报告与"可删清单"

导完给一页报告，四个数字：新增 / 重复 / 失败 / 跳过。下面是可以展开的三张清单：重复项（保留哪张、丢弃哪张）、失败项（文件名 + 原因）、**可删源文件**。

可删清单是"敢删手机"的核心。一条源文件只有同时满足三条才进清单：

1. 原图已进入私库，且 `sha256` 一致；
2. 派生图已生成（缩略图能看）；
3. 私库根目录已出现在备份位置（§14）。

不满足就给理由，不给"忽略并继续"的按钮——那个按钮等于让用户自己骗自己。

条件 3 怎么验证（P0 一起做；不做，P0 的验收就过不了）：

- `npm run nest:backup`：把 `originals/` 与 `library.db` 增量拷到 `NEST_BACKUP_HOME`（外置硬盘或网盘目录），写一份 `backup-manifest.json`：每个文件的路径、字节数、sha256、生成时间。
- 生成可删清单时校验三件事：备份根目录在不在；清单时间是否晚于这些照片的 `imported_at`；对清单里**每一条要删的文件实际读首块和尾块**并复核哈希。读字节不是为了严格（全量校验另有命令），是为了让网盘的"按需下载"占位文件现原形——占位文件在元数据里"存在"，内容却是空的。
- 结果写进 `backup_check` 表。外置硬盘拔了，清单一律失效，提示"接上备份盘再删"，没有跳过按钮。校验慢可以接受：删手机照片是一辈子做几次的事。

### 6.4 多台手机

导入批次带一个名字（"红米 Note 12 旧手机"）。同一台手机导两次不会产生重复（`sha256` 挡住）。每台手机在 `/studio/sources` 里一行，显示"已导入 X 张，最后一次 2026-10-20"，这样"哪台清过了"不需要记在脑子里。

### 6.5 幂等与可撤销

同一批文件重复导入必须得到完全相同的结果（除 `imported_at`）。导入不是事务性的"全成功或全失败"：单张失败不影响别人。撤销的最小单位是批次——`nest:import:undo <batch>` 把该批次新增的 asset 标成 `trashed`，不进回收站之外的连锁删除。

## 7. 私库页面（`/studio`）

只在本地跑，所以设计取向是**干活效率**，不是好看。

- **收件箱** `/studio`：最近导入的照片，默认全选"未归类"。这里做减法：删、进相册、加标签。
- **浏览** `/studio/browse`：同公开页的三轴（时间/地点/标签），但多一个"含私密"的开关，默认全都有。
- **搜索**：输入框，语义 + 全文 + 结构化混用。这里才有真本事（公开页只有发布出去的那部分）。
- **重复** `/studio/duplicates`：相似组一屏看，一键保留最优（分辨率最高、有 GPS 的优先）。
- **相册** `/studio/albums`：建相册、拖照片进去、设封面。
- **发布** `/studio/publish`：见 §10。
- **维护** `/studio/maintenance`：回收站、没 GPS 的、时间估计的、备份状态。

### 8.1 头

照博客的开法：eyebrow 小字（`相册`）、大标题、一句实话、`mono` 数字。数字三个：张数、城市数、年份跨度。这三个数字本身就是"回看"的第一个答案。

搜索框放在头部右侧，`/` 快捷键聚焦，不占一整个 hero。

### 8.2 足迹地图（主舞台，占屏宽 2/3）

- 默认中国视图。城市是一个点，点半径按 `√照片数` 映射（3–14px），颜色是品牌绿的浓度档。
- 点 hover：浮出小卡——城市名、年份跨度、张数、一张封面缩略图。点进去到 `/photos/place/[city]`。
- 地图下方一句由数据生成的事实："你去过 23 个城市，最北到哈尔滨，最南到三亚。" 这句话随筛选变，是这一页的性格所在。
- 中国/世界切换在右上角，小到不抢戏。
- 没有坐标的照片（截图、笔记配图）不进地图，但进时间轴——地图只统计"知道在哪"的。
- 二期加成（P3，不阻塞）：一条年份滑块拖过去，点一个个亮起来。这是整个页面最"回看"的一下，但先要有真数据才谈得上。

### 8.3 归类（右栏，1/3 宽）

三组，每组是带计数的圆角 chip（沿用博客的 topic chip 样式，不新造）：

- **相册**：你手挑的，最多的五六个。有封面、名字、张数。
- **地点**：按张数排序的前几个城市。
- **主题**：标签，按计数。这是"狗 24"出现的地方。

移动端：地图在上，三组 chips 改成横向滚动条；不做 tab，因为一次能看见三类入口比分类切换更符合"随手翻"。

### 8.4 时间轴

按年分组，每年一行：`年份 · 月度密度条 · 张数 · 首排缩略图 · 全部 →`。

月度密度条用博客归档页已经有的手法（12 个格子，深浅=张数），一致性白送。

点年份进 `/photos/year/[year]`，那就是一堵照片墙（不等高网格，见 §9）。

### 8.5 搜索

- 输入即搜，防抖 120ms，结果直接替换下面的内容区，不跳页。
- 命中的依据：概念标签 → 中文别名表；描述文本；相册名；城市名；年月。结果按相关度 + 时间倒序混排（同一相关度下新的在前）。
- 空结果说人话："没有和'小狗'对上的照片。"再给一行提示："试试城市名、年份、或者'海'、'山'、'夜'。"
- 结构化筛选以 chip 追加到搜索框后面：`小狗` `2023` `杭州`，每个 chip 可单独摘掉。

### 8.6 照片详情 `/photos/photo/[id]`

大图居中，右边是元数据：时间、地点（可点到城市）、相机、相册、一句你写的说明。下面"同一天"和"同一地点"各一排。键盘 `←/→` 翻到时间上的前一张/后一张，`Esc` 回列表。

### 8.7 空状态与"诚实"

站上博客那句"还没有文章——这个博客是慢慢攒的"是这一站的语气。相册沿用：没照片的时候就是"还没有照片，这个相册刚开张"，不摆假种子数据。地图上没点的时候也不放示例点。

## 9. 视觉语言

**沿用**（不新造一套"相册风格"）：

- eyebrow 小字 + 大标题 + 斜体不需要，语气靠内容。
- 细线分隔（`border/60`），年份轴用 `h-px flex-1` 那条。
- 数字全部等宽字体（`font-mono`），中文用站酷快乐体，两者并置已经是站点的记号。
- 品牌绿只用在：地图点、"当前选中"、可点的强调。照片本身有颜色，界面要退后。
- 动效 200–350ms，卡片 hover 只改边框和阴影，**不位移**（避免 layout shift）。

**例外**：

- 照片墙用不等高网格（CSS `columns` 或 flex 列），不用等宽卡片——等宽会把竖图和横图裁得一样，难看。
- 地图区域允许比别处更暗：一个近黑的底，细线国界，让绿点跳出来。
- 加载占位用 32px 的 base64 主色模糊图（`next/image` 原生支持），不做骨架屏闪烁。

## 10. 发布流水线

`/studio/publish` 或者 `npm run album:publish`：

1. 选照片/相册（默认是上次发布之后新标记为"公开"的）。
2. 生成派生：只保留 `w2400` 一份 webp（其余尺寸交给 `next/image` 派生并缓存），写入 `public/album/<年>/<id>.webp`。
3. 生成数据：`src/data/album.ts`（照片、相册、地点聚合、统计数字）。
4. 生成索引：`public/album/search-index.json`（minisearch 序列化），只含 caption/标签/地点/年月。
5. 生成地图：`src/generated/geo.ts`（如果 GeoJSON 变了才重写；地图点数据来自 album.ts）。
6. 打印 diff 摘要：新增 N 张、移除 M 张、总体积 +X MB。
7. **不自动 commit、不自动 push**。让人看一眼数字再提交——这一步的错误代价是公开泄露，不能自动化。

每次发布一个 commit，不 squash——一次误发可以单独 revert。

**撤回** = 把照片的 `visibility` 改回 private（或取消相册公开），重跑发布，提交一次删除。这里要说清两件事：

- **仓库是公开的。** 删除提交只让它在 URL 上消失，历史里、已经 fork 出去的地方都还在。所以"撤回"的承诺是"下次构建之后不再展示"，不是"抹掉"。真要抹掉得改写历史 + force push，把步骤写进 README 备查，不作为常规操作。
- **撤回记录只存在私库**，一条就够："2026-11-02 撤回 3 张，原因：拍到了别人家的孩子。" 不放到公开站上——那等于把"我撤回过什么"也公开了。

## 11. 性能与可访问性

- 首屏：地图（SVG，几十 KB）+ 头。照片墙懒加载，`loading="lazy"`，每张图 `sizes` 明确。
- 公开页面全部预渲染；没有客户端数据请求（除搜索索引，聚焦时才取）。
- 搜索：索引 gzip 后目标 < 120KB；超过就把索引按年分片。
- 键盘：地图点可 Tab 聚焦，focus ring 用 `--ring`（19:1）；搜索框 `Esc` 清空；详情页方向键翻页。
- `prefers-reduced-motion`：地图不做入场动画，hover 卡直接出现。
- 亮色模式同样可用：地图底改成浅灰，绿点加深一档。设计系统里两套 token 已经在了，不要为地图硬编码颜色。
- 触屏：地图点最小点击区域 44×44（视觉上可以小，热区用透明圈补）。

## 12. 双语

站上是 zh/en 双栏字典。相册的文案放 `src/config/photos-labels.ts`，照 `blog-labels.ts` 的样子（这是这个项目的既有惯例）。

但**地名**不跟界面语言走：中文界面写"杭州"，英文界面写 "Hangzhou"，来自 `place.name` / `place.name_en`。城市名翻不翻是内容问题，不是界面问题。

## 13. 分期

| 期 | 内容 | 完成判据 |
|---|---|---|
| P0 | 私库数据层 + 导入 CLI（扫描/去重/EXIF/派生/城市）+ 备份校验 + 报告 | 用一份真实的手机备份导入 1000 张，得到可删清单，`library.db` 里数据正确 |
| P1 | `/studio` 浏览 + 搜索 + 收件箱 + 手机上传 + 监视文件夹 | 能只靠网页把新照片归进相册、删掉废片 |
| P2 | 公开发布流水线 + `/photos`（头、地图、归类、时间轴、搜索、详情） | `/photos` 上线，只有发布过的照片，地图与数字对得上 |
| P3 | CLIP 概念标签 + Ollama 描述 + 相似组 + 自动行程（连续多天同城 → "京都 5 天"） | 搜"小狗"确实出狗，相似组不误伤 |

P0 和 P1 之间没有 UI 依赖，可以并行，但 P0 必须先于 P2 完成，否则 P2 是在给假数据做壳子。

P0 的素材决定导入启发式先做哪些：手上那台手机的备份是 iPhone 的 HEIC、小米/红米的 DCIM、Google Takeout（按年分目录 + sidecar JSON），还是网盘镜像。没有现成备份就先按"jpg + DCIM 目录"的形状做，HEIC 与 sidecar 走同一条路径但排在后面——这一条要先确认，见 §16。

## 14. 风险与对策

| 风险 | 对策 |
|---|---|
| 硬盘坏了，手机也删了 → 照片全没 | 发布/可删清单要求"私库根目录已出现在备份位置"。备份可以是外置硬盘或网盘，软链接过去即可。这个检查不做成可跳过。 |
| 8000 张导入到一半崩溃 | 每张图独立完成，`sha256` 保证重跑幂等。批次有 `finished_at`，没完成的重跑会从剩下的继续。 |
| 私库被公网访问 | 只监听 `127.0.0.1`；`/studio` 在 Vercel 上 404；手机上传走局域网 IP，不外网穿透（真需要再加隧道 + 口令，那时再谈）。 |
| 公开站体积撑爆仓库 | 一期 300 张上限，超了切对象存储（§4.3）。发布时打印体积，超预算直接拒绝。 |
| 中文查询搜不到（CLIP 只有英文） | 别名表 + 固定概念词表，不做自由语言承诺（§4.4）。 |
| 反查城市出现"杭州 3 张"实际在富阳 | 地点聚合到"市"这一级，不往下钻；用户可以手动改一张照片的地点（`/studio` 里可编辑）。 |
| 照片越来越多，地图点挤成一团 | 点是按城市聚合的，不是按张。城市数是有上限的。 |

## 15. 留给建造者的

这些可以自己定，不需要回来问：

- 组件怎么切、文件放哪。建议 `components/photos/*` 一目录，`lib/album/*` 放数据与格式化。
- 地图投影的 padding / 视野边界，做法是找几个极端点（三亚、漠河、喀什）试到不出界。
- 不等高网格用 `columns` 还是 flex 列（选在移动端不跳的那个）。
- 搜索相关度的权重（标签命中 > 描述命中 > 地点命中）。
- 导入队列的并发数与进度上报的粒度。
- 具体文案（语气照 §8.7 和博客的既有腔调）。

## 16. 还差你定的两件事

不是设计问题，是只有你知道的事实。答案会改 P0 的做法，所以我没替你猜。

1. **备份放在哪、算不算数。** 可删清单卡在这一条上（§6.3）。有没有一个外置硬盘、NAS，或者一个你信得过的网盘目录？愿不愿意让 `nest:backup` 往那儿写？如果答案是"没有备份"，这一期就只做到入库和浏览，删手机照片往后放——这不是设计上的选择，是物理上的。
2. **P0 拿什么验。** 哪台手机、备份出来是什么形态（iPhone HEIC / 小米 DCIM / Google Takeout / 网盘镜像）。它决定导入先支持哪种，以及验收用真照片还是合成样本。
